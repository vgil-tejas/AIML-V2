Install & run CyberSentinel on a server

Two ways to install: A) from the GitHub repository (builds on the server), or B) from the offline image bundle (no source, for banks). Both end with the dashboard on http://<server>:18888. Then configure the AI key, and rotate it any time.

1. Prerequisites — install Docker (one time)

On a fresh Ubuntu/Debian server, install Docker Engine + the Compose plugin:

# quickest — official convenience script
curl -fsSL https://get.docker.com | sudo sh

# let your user run docker without sudo, then log out and back in
sudo usermod -aG docker $USER

# verify (need Docker 24+ and the compose v2 plugin)
docker --version
docker compose version
RHEL/CentOS: the same convenience script works. Minimum server: 16 GB RAM, 50 GB disk, and port 18888 reachable by analysts.

2. Option A — Install from GitHub (builds on the server)

Use this when you have access to the repository (self-managed / your own servers).

  1. Get the code. 
    git clone https://github.com/Tejasvgipl/AIML-V3.git
cd AIML-V3
    Private repo → when Git asks for a password, paste a GitHub Personal Access Token (not your login password), or run gh auth login first.
  2. Configure secrets (AI key + event-store password), interactively: 
    ./scripts/setup.sh
    Pick an AI mode (Groq cloud / on-prem LLM / disabled — see §5). This writes .env (permissions 600, never committed).
  3. Build & start the full stack, including log ingestion: 
    docker compose --profile wazuh up -d --build
    The first build takes a few minutes; later starts are instant.
  4. Verify & open. 
    curl -s localhost:18888/api/health
# {"status":"ok","store":"connected","ai":"configured"|"missing"}
    Open http://<server-ip>:18888 in a browser.
Update later: git pull then docker compose --profile wazuh up -d --build. The data volume is preserved.

3. Option B — Install from the offline image bundle (no source)

Use this for a customer/bank server that must not receive the source code. You hand over the cybersentinel-<version>/ bundle folder (built with scripts/package.sh).

  1. Copy the bundle folder to the server and enter it: 
    cd cybersentinel-2.0.0
  2. Run the one-command installer: 
    ./run.sh
    It loads the images from images.tar.gz, runs setup.sh for the AI key + store password on first run, and starts the stack.
  3. Verify & open — same as above: curl -s localhost:18888/api/health, then http://<server>:18888.
Build the bundle (on your machine, one command): ./scripts/package.sh 2.0.0 → produces dist/cybersentinel-2.0.0/ with no source inside.

4. Point log ingestion at your alerts

The watcher reads your alerts.json read-only and streams events into the store. Set the path in .env, then restart with the ingestion profile:

# in .env
WAZUH_ALERTS_DIR=/var/ossec/logs/alerts     # directory holding alerts.json

# apply
docker compose --profile wazuh up -d                                # GitHub install
docker compose -f docker-compose.prod.yml --profile wazuh up -d     # bundle install

5. AI analyst & API key

The AI analyst powers SOC Query, alert explanations and incident narratives. It is the only feature that can send data outside the server, and only when an analyst clicks an AI panel or runs a query — never automatically. Configure it with:

./scripts/setup.sh
ModeYou enterData leaves the server?
1 · CloudYour Groq API keyYes — short log snippets, on-demand only
2 · On-prem LLMYour OpenAI-compatible URL + key + modelNo — stays inside your network
3 · DisablednothingNo — zero external calls
Where the key lives: only in the local .env file (chmod 600, never in the images, never committed). Each server has its own.

Setting it manually in .env

# Cloud (Groq):
GROQ_API_KEY=your-key-here

# On-prem / self-hosted OpenAI-compatible endpoint:
GROQ_API_KEY=
AI_BASE_URL=https://llm.internal.bank/v1/chat/completions
AI_API_KEY=your-endpoint-key
AI_MODEL=your-model
AI_FAST_MODEL=your-model

# Disabled: leave GROQ_API_KEY and AI_API_KEY empty

6. Change / rotate the API key

No code change and no rebuild — it is runtime config:

  1. Re-run the configurator (or edit .env): ./scripts/setup.sh
  2. Recreate the backend so it reads the new value: 
    docker compose up -d backend                              # GitHub install
docker compose -f docker-compose.prod.yml up -d backend   # bundle install
  3. Confirm: curl -s localhost:18888/api/health → "ai":"configured"
A plain docker restart is not enough — env values are read when the container is created, so use up -d backend to recreate it.

7. Ports & store password

All overridable in .env:

VariableDefaultPurpose
NGINX_HOST_PORT18888Dashboard + API (the analyst URL)
BACKEND_HOST_PORT18110Backend (direct)
ML_ENGINE_HOST_PORT18111ML engine (direct)
CLICKHOUSE_PASS—Event-store password (set via setup.sh)
Never run docker compose ... down -v — the -v deletes the data volume (your entire log store). Plain down keeps the data.

9. Troubleshooting

SymptomWhat to check
Dashboard won't loaddocker compose ps — is the backend healthy? curl localhost:18888/api/health
AI panels say "not configured"No key set — run ./scripts/setup.sh, then up -d backend
SOC Query says "service busy"AI provider rate-limited — retry shortly, or use a paid tier / on-prem model
Store connection_faileddocker compose logs clickhouse; confirm CLICKHOUSE_PASS in .env
No events appearCheck WAZUH_ALERTS_DIR and logs -f wazuh-watcher
Private clone failsUse a GitHub Personal Access Token as the password, or gh auth login
Health one-liner: curl -s localhost:18888/api/health should return "store":"connected".
